# 01：現況盤點

**目標**：建立 AI 資源、存取方式與高權限的基準。本 Lab 全程唯讀，約 30 分鐘；先完成[前置準備](../prerequisites/)。

## 操作一：資源與驗證方式

1. 在 Azure Portal 的目標訂用帳戶列出 Foundry / Azure OpenAI 與 APIM 資源。
2. 逐一檢查 AI 資源的 **JSON View** 中 `properties.disableLocalAuth` 與 `properties.publicNetworkAccess`。缺少屬性時標為「待確認」，不能當作已安全。
3. 檢視 **Networking** 與 **Access control (IAM)**，記下直接及繼承的模型資料平面權限。不要開啟或匯出金鑰。
4. 檢查診斷設定、模型部署及 APIM SKU。為每個資源補上負責人與用途，只保存在受控位置。

以下為可自行填寫的**匿名化**紀錄格式：

| 資源代號 | 用途 | 本機驗證已停用 | 公用網路狀態 | 直連身分已檢視 | 待辦 |
|----------|------|----------------|--------------|----------------|------|
| AI-A | 教學測試 | 待確認 | 待確認 | 否 | 指定負責人後查核 |

公用網路啟用不等於任何人皆有推論權限；金鑰停用也不等於網路已隔離，必須分別判讀。

## 操作二：管理角色

1. 在 Microsoft Entra admin center → **Roles & admins → Global Administrator → Assignments** 查看指派與範圍。遇到群組時，依權限檢視其成員；讀取不足時請管理者協助，不自行升權。
2. 在 Azure 訂用帳戶 → **Access control (IAM) → Role assignments**，檢視 Owner、User Access Administrator 與其他可管理角色指派的角色，包含繼承來源。
3. 區分使用者、群組與服務主體，逐項確認用途、負責人與複核日期。不要只計算顯示的資料列就當作人數。
4. 確認是否已有至少兩個經驗證的緊急存取帳號，以及管理與日常身分是否分離。此處只盤點，**不移除任何角色**。

## 操作三：找出優先處理項目

每題給 0 / 1 / 2 分：未做或不清楚 / 部分完成 / 已有證據。這是學習自評，不是合規評鑑。

| 構面 | 問題 |
|------|------|
| 金鑰 | 模型資源是否已停用本機金鑰，例外是否獲核准？ |
| 金鑰 | 應用是否已移除程式碼與 Notebook 中的金鑰？ |
| 金鑰 | 必要的 Gateway 憑證是否有獨立負責人與輪替紀錄？ |
| 用量 | 各應用是否有 TPM 與期間配額？ |
| 用量 | 能否依應用查詢用量與失敗原因？ |
| 用量 | 異常警示與預算通知是否實際測試？ |
| 身分 | 每項高權限是否有必要性與複核日期？ |
| 身分 | 緊急帳號是否已驗證，管理帳號是否使用 MFA？ |
| 身分 | 日常工作是否在最小必要範圍授權？ |

選出三項缺口，記下負責角色、證據與預定完成日。缺少可用的緊急存取機制時，先安排[身分治理](../entra-governance/)演練，再進行角色收斂。

## 驗收與清理

應有三份受控紀錄：資源清冊、角色責任表與改善優先序。**只繳交匿名化摘要**，不公開原始帳號或環境 ID。

本 Lab 無資源變更；刪除不需要的本機暫存輸出。沒有讀取權限或查不到資料時，記為待確認，不填「無風險」。
